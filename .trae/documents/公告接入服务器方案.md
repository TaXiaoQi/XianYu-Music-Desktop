# 公告功能接入服务器方案

## Context（背景与目标）

当前桌面端的公告数据源是 GitHub 仓库 `ShenYichenCN/XianYu-Music-Desktop` 根目录的 `announcement.json`（由 Rust 命令 `fetch_announcement` 拉取三个 GitHub raw / 代理 URL）。每次发公告都要改 JSON、commit、push，且无法在后台可视化编辑。

目标：把公告接入已部署的后端服务器（`xy.zh2026.cn`，PHP + MySQL 后台 `网页端/后台/chaoguan`），实现：
- **后端可视化编辑发布**：管理员在 Web 后台管理公告（增删改查 + 启用/禁用），仿现有「版本管理」页
- **桌面端实时拉取**：应用启动时从服务器拉取最新启用公告，**移除 GitHub 数据源**（删除 `announcement.json` 和三源 fallback）

### 用户确认的关键决策
1. 公告模型：**多条列表管理**，每条有 `enabled` 字段，桌面端只取「最新一条 enabled=1」
2. 桌面端：**纯服务器**，移除 GitHub 容灾
3. API 地址：`https://xy.zh2026.cn/chaoguan/public/api/app.php`（chaoguan 是子路径）

## 架构总览

两条独立路径：

```
① Web 后台管理（管理员编辑公告）
   浏览器 → pages/announcements.php（列表+表单）
        → JS api({action}) POST → index.php handleAjax()
        → PHP 函数直接 PDO 操作 app_announcements 表
   鉴权：session（Auth::requireLogin，与 version 管理一致）

② 桌面端拉取（用户看公告）
   Tauri 应用 → invoke('fetch_announcement')
        → Rust GET https://xy.zh2026.cn/chaoguan/public/api/app.php?action=app_announcement
        → app.php 免签接口读 DB 最新 enabled=1 公告
   鉴权：无（公开接口，加入 $noSignActions 白名单）
```

## 数据库表设计

新建表 `app_announcements`：

```sql
CREATE TABLE IF NOT EXISTS `app_announcements` (
    `id` bigint unsigned NOT NULL AUTO_INCREMENT,
    `title` varchar(128) NOT NULL DEFAULT '',
    `content` text NOT NULL,
    `type` varchar(16) NOT NULL DEFAULT 'info' COMMENT 'info/warning/update',
    `action_url` varchar(512) NOT NULL DEFAULT '',
    `action_text` varchar(64) NOT NULL DEFAULT '',
    `enabled` tinyint(1) NOT NULL DEFAULT 0 COMMENT '1启用 0禁用',
    `created_at` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP,
    `updated_at` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (`id`),
    KEY `idx_enabled_created` (`enabled`, `created_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='应用公告';
```

**公告 `id` 策略**：桌面端 dismissed 机制（localStorage 存 id）依赖 id 稳定。用数据库自增 id 转字符串作为公告 id。新增公告→新 id→所有用户重看；编辑已有公告→id 不变→已 dismiss 用户不看（符合预期，与现有行为一致）。

**d. `handleAppAnnouncement` 函数**：查询最新一条 `enabled=1` 公告，返回格式与现有 `announcement.json` 字段对齐（兼容前端 `Announcement` 接口）：
```php
function handleAppAnnouncement(PDO $pdo) {
    $stmt = $pdo->prepare("SELECT id, title, content, type, action_url, action_text, created_at
                           FROM app_announcements WHERE enabled = 1
                           ORDER BY id DESC LIMIT 1");
    $stmt->execute();
    $row = $stmt->fetch(PDO::FETCH_ASSOC);
    if (!$row) {
        AppSign::jsonResponse(200, 'ok', null);  // 无公告，data=null
    }
    AppSign::jsonResponse(200, 'ok', [
        'id'          => strval($row['id']),
        'title'       => $row['title'],
        'content'     => $row['content'],
        'type'        => $row['type'] ?: 'info',
        'date'        => substr($row['created_at'], 0, 10),
        'actionUrl'   => $row['action_url'],
        'actionText'  => $row['action_text'],
    ]);
}
```

## 前端实现（Tauri 桌面端）

### 1. Rust 命令 `fetch_announcement`（`src-tauri/src/toolbox.rs`，约 L789）

改造为请求服务器 + 解包响应：
```rust
#[tauri::command]
pub async fn fetch_announcement() -> Result<String, String> {
    let url = "https://xy.zh2026.cn/chaoguan/public/api/app.php?action=app_announcement";
    let client = reqwest::Client::builder()
        .timeout(Duration::from_secs(8))
        .user_agent("XY-Music-Updater")
        .build()
        .map_err(|e| format!("创建请求客户端失败: {e}"))?;
    let text = client.get(url)
        .header("Accept", "application/json")
        .header("Cache-Control", "no-cache")
        .send().await
        .map_err(|e| format!("请求公告接口失败: {e}"))?
        .error_for_status()
        .map_err(|e| format!("公告接口返回错误状态: {e}"))?
        .text().await
        .map_err(|e| format!("读取公告数据失败: {e}"))?;
    // 解包 {code, msg, data}：仅 code==200 且 data 非空时返回 data 的 JSON
    if let Ok(v) = serde_json::from_str::<serde_json::Value>(&text) {
        if v.get("code").and_then(|c| c.as_i64()) == Some(200) {
            match v.get("data") {
                Some(d) if !d.is_null() => return Ok(d.to_string()),
                _ => return Ok("{}".to_string()),  // 无启用公告
            }
        }
        return Err(format!("公告接口返回错误: {}",
            v.get("msg").and_then(|m| m.as_str()).unwrap_or("未知")));
    }
    Err("公告数据解析失败".to_string())
}
```
**关键**：Rust 解包后返回纯公告对象 JSON，前端 `Announcement` 接口完全不用改字段。删除原三源 URL 循环 + `no_proxy()`。
